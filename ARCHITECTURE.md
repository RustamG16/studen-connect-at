# ARCHITECTURE — Care4Students

## Runtime and stack

Single-page app generated by Lovable, kept as is: Vite 5 (`@vitejs/plugin-react-swc`), React 18,
TypeScript 5, Tailwind CSS 3 (`tailwindcss-animate`, `@tailwindcss/typography`), shadcn/ui on Radix
primitives (49 components in `src/components/ui`), react-router-dom 6, TanStack Query 5 (instantiated, not
used for data), react-hook-form + zod, lucide-react, lottie-react, recharts, sonner. Package manager: npm
(`package-lock.json`; `bun.lockb` is also committed but npm is the source). Dev server on port 8080.

Why keep it: the brief is a redesign, not a rebuild. Keeping the stack keeps routes, auth and every copy string
stable, and lets the redesign swap tokens, layout and motion without rewiring.

Dev-only: `lovable-tagger` runs in `development` mode only (`vite.config.ts`).

Boundaries for the redesign:
- Redesign scope: `src/index.css`, `tailwind.config.ts`, `index.html`, `src/components/{Navbar,Footer,LoadingScreen,AnimatedLogo}.tsx`,
  new components, and the public pages `Index, Bonuses, Housing, FindBuddy, HowItWorks, FAQ, Contact, Legal, Blog, Login, Signup, NotFound`.
- Frozen in behaviour: `AuthContext.tsx`, `ProtectedRoute.tsx`, the route table in `App.tsx`, `Dashboard*.tsx`, `DashboardSidebar.tsx`.
  Token changes must leave dashboard pages legible; fix regressions, do not redesign them.
- Because `Navbar`/`Footer` may be shared with the dashboard, check before restyling globally.

## Interfaces and state

Routes (`src/App.tsx`):

| Path | Page | Access |
|---|---|---|
| `/` | Index | public |
| `/bonuses` | Bonuses | public |
| `/how-it-works` | HowItWorks | public (nav label "Guide") |
| `/housing` | Housing | public |
| `/find-buddy` | FindBuddy | public |
| `/faq` `/contact` `/legal` `/blog` | FAQ, Contact, Legal, Blog | public |
| `/login` `/signup` | Login, Signup | public |
| `/dashboard`, `/dashboard/{bonuses,housing,buddy,documents,support,settings}` | Dashboard* | `ProtectedRoute` |
| `*` | NotFound | public |

Nav labels (Navbar): Home, Bonuses, Housing, Find Buddy, Guide, FAQ; auth state swaps in Dashboard and a user menu.

State: `AuthContext` holds `{user, isAuthenticated, login, signup, logout, loading}`. Login/signup are
`setTimeout` mocks that accept any email + password (signup needs ≥ 6 chars) and persist `{id,email,name}`
in `localStorage["user"]`. No other persistence, no network calls, no env vars, no secrets.

`App` shows `LoadingScreen` (Lottie logo, 4 s fallback) on every full load.

## Build, verification and deployment

- Install: `npm ci`. Dev: `npm run dev`. Build: `npm run build` (baseline passes, ~7 s; one 1.06 MB JS chunk, 95 kB CSS). Lint: `npm run lint`.
- No test runner is configured. Verification is build + lint + browser checks (screenshots at 360, 390, 768, 1280 px, reduced motion, console clean).
- Deploy: Netlify from the repo, site https://care4students.netlify.app/. The repo has no `netlify.toml` or `public/_redirects`, so
  direct deep links depend on dashboard-side SPA fallback. Adding a `_redirects` (`/* /index.html 200`) is a safe, in-scope hardening.
- Relay sessions commit to branch `redesign-2026` and never push.

## Decisions and costs

- Keep the Lovable stack (above). Cost: shadcn defaults leak through unless tokens and component variants are overridden.
- The redesign replaces Manrope and the teal/navy tokens in `src/index.css`. Cost: the dashboard shares those tokens and must be re-checked.
- Fonts: `index.html` still links Nunito while the CSS uses Manrope from `@fontsource/manrope`. Redesign picks one pipeline (self-hosted `@fontsource`), removes the stale link.
- Motion and 3D libraries are not installed yet. Any addition (GSAP, Lenis, Three) is a plan-level decision with a bundle budget; lazy-load and gate on `prefers-reduced-motion`.
- `CARE4STUDS_CODEPILOT_STYLE_MIGRATION_GUIDE.md` asks for an exact Education4Students match. The newer brief (same family, own style) wins; see `PROGRESS-AND-DECISIONS.md`.
